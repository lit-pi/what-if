# What-If 作为 Silicon Factory 下游系统

## 决策

What-If Life Simulator 是一个新的下游产品，不是 Silicon Factory / Persona Library 内部的一个功能。

Silicon Factory 继续作为上游系统，负责人格资产、角色维度模型、记忆种子、剧本约束和质量门禁。What-If 负责面向用户的玩法循环、剧本运行时、GM 规则、视觉呈现和结局 / 分享体验。

## 为什么要拆开

Silicon Factory 当前回答的问题是：

- 这个人格或 Agent 是什么类型？
- 他们的价值观、目标、记忆、约束和行为模式是什么？
- 这个人格是否足够好，可以用于模拟或交付？

What-If 回答的是另一组问题：

- 玩家现在正在做什么？
- 本回合有哪些 AI 角色正在向玩家施压？
- 哪些状态变化能让故事具备复玩性？
- 应该触发哪个结局，为什么？
- 什么 UI 反馈能让玩家感到蝴蝶效应？

保持 What-If 的下游独立性，可以先让产品需求变具体，再决定是否需要推动上游 schema 变化。

## 未来期待的上游能力

What-If 未来应向 Silicon Factory 请求：

- AI 角色的人格包。
- 每个 AI 角色稳定的价值观、目标、说话风格和记忆种子。
- 维持世界一致性的剧本约束。
- 生成角色行为的安全与质量评审。
- 可选的多 Agent 回合编排辅助。

## 下游在本仓库拥有的能力

What-If 负责：

- 剧本目录和剧本选择。
- 游玩会话状态。
- GM 裁决规则。
- 场景图和插入事件。
- AI 角色主动意图触发。
- 回合输出 schema。
- 结局优先级和复玩反馈。
- 移动端优先 UI 和分享卡。
- 视觉资产提示词库。

## 反向反馈给 Silicon Factory

第一个剧本 `undercover-demon-king` 是需求探针。等它被实现为可玩的原型后，应反向推动上游变化，例如：

- 支持非人类 / 双重身份人格。
- 按游玩会话记录的角色记忆日志。
- 证据、怀疑、信任和关系状态 primitive。
- 多 Agent 回合打包。
- 基于真实失败模式的 GM 输出质量检查。

下游产品应该迫使上游需求变清晰，而不是反过来。
