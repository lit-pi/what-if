# 《假如我是勇者队伍里的卧底魔王》MVP 1.0 QA 计划

状态：可执行  
范围：当前零依赖静态 demo，入口 `index.html`，运行时 `src/app.js`。

## 1. QA 目标

本轮 QA 不追求系统大扩展，只确认当前 demo 已经足够稳定，可以作为后续 LLM/上游人格包接入前的基线。

必须证明：

- 玩家能从开局玩到结局。
- 7 个场景节点都能被到达。
- 预设行动和自由行动都能稳定产生状态变化。
- 即时结局、硬失败结局和终局结局不会空白。
- 结算页能解释关键原因。
- 运行时仍然零依赖、可快速预览。

## 2. 自动检查

每次改动 `src/app.js` 后运行：

```bash
pnpm check
pnpm test:runtime
```

自动检查覆盖：

- JavaScript 语法。
- 场景 key 唯一且入口 `gate` 存在。
- 每个 `nextSceneId` 都指向存在的场景。
- 每个 `endingKey` 都指向存在的结局。
- 每个 `ENDINGS.xxx` 引用都存在。
- 状态 delta 只写已定义状态字段。
- 角色对话只引用已定义角色。
- 图片资源存在。
- Runtime v1 关键场景、状态、结局、旗标 key 没有从代码中意外漂移。

## 3. 手工验收清单

桌面与移动窄屏都至少检查一次：

- 开始页视觉完整，主 CTA 清晰。
- 开局后没有顶部常驻数值条造成信息拥挤。
- 中央角色焦点不遮挡关键对白和按钮。
- 对白逐条推进时，当前说话角色、表情和背景不跳动。
- 选择面板展开后，三个预设选择都能点击。
- 自由输入能提交，空输入不会破坏流程。
- 回合结果页显示行动、裁决、状态变化和角色反应。
- 转场黑幕不会露出半截旧场景。
- 结算页显示结局标题、类型、原因解释和重开入口。

## 6. 终局结局测试建议

当前 Runtime v1 的部分终局结局由阈值自然达成，部分需要继续调参。QA 时先记录“是否可自然到达”，不要急着为了覆盖率加入重型系统。

优先测试：

- `victorBlamed`：王座厅选择甩锅维克托。
- `absurdAscension`：王座厅选择主题乐园。
- `dualRuler` 或 `redeemed`：多次保护/和平倾向后，在王座厅选择和平。
- `perfectSpy`：低暴露、高信任、城防较高路线。
- `exposed`：自由行动直接承认魔王身份，或让暴露风险冲到 75。
- `instantArrest`：让法师证据达到 65 或暴露风险达到 75，但未使用具体陷阱 `endingKey`。
- `stalemate`：走到王座厅但不满足其他优先条件。

下一阶段实现红线 validator 后，额外检查：

- `thiefLeverage >= 70` 时，王座甩锅不能无条件进入最好甩锅解释，应转为二次勒索、僵局或带代价结局。
- `heroTrust < 40` 时，不能进入 `dualRuler`、`redeemed`、`perfectSpy`。
- `sacrificedInnocentsCount > 0` 且 `priestRedemption` 不足时，和平结局应被阻断。

如果某个终局只能靠开发者手动改状态才能到达，应在调参记录中标记为“不可自然到达”，再决定是否降低阈值或增加可见行动。

调参优先级：

1. 先解决空白结局、断链、无法继续。
2. 再解决玩家看不懂为什么输/赢。
3. 再调整数值，让至少 6 个结局可被有意触达。
4. 最后才考虑 LLM 文案质量和角色多 Agent 行为。
