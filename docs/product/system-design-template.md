# What-If 系统设计模板

当某个玩法系统重要到会影响玩家决策、GM 裁决、AI 行为或结局时，使用这个模板。

每份文档都应保持简短。目的不是制造流程负担，而是让实现更安全。

## 系统名称

名称：

状态：

- 草稿
- 可进入原型
- 已实现
- 需要试玩

## 玩家幻想

因为这个系统存在，玩家应该感觉自己能做什么？或相信自己正在经历什么？

## 运行时目的

这个系统在一次游玩会话中负责决定什么？

示例：

- 本回合哪个 AI 角色发言。
- 自由行动如何被判断。
- 证据是否公开。
- 当多个结局条件同时满足时，哪个结局胜出。

## 输入

列出这个系统读取的状态字段、旗标、场景数据、玩家行动和角色记忆。

## 输出

列出这个系统写入的状态变化、旗标、UI 事件、叙述槽位、角色反应或结局候选。

## 规则

用确定性语言描述规则。

尽量使用区间、阈值、优先级顺序和兜底行为。

## AI 边界

LLM 可以建议什么？

哪些内容必须由运行时自己决定？

## UI 反馈

这个系统执行后，玩家应该看到什么？

示例：

- 状态变化标签。
- 角色警告标签。
- 证据卡。
- 插入事件横幅。
- 结算页因果说明。

## 边界情况

列出失败模式和必须存在的兜底处理。

示例：

- 多个结局同时有效。
- 自由行动试图一句话解决整个故事。
- 某个状态到达 `0` 或 `100`。
- 某个角色应该反应，但不在当前场景。

## 调参旋钮

哪些值可以在试玩后调整？

示例：

- 阈值。
- 状态变化范围。
- 冷却时间。
- 场景转场要求。
- 结局条件。

## 验收标准

系统满足以下条件时，才算可以推进：

- 有确定性的兜底行为。
- 如果影响结局，就能在结算页解释。
- 至少可以通过一条正常路径和一条边界路径测试。
- 不依赖不受约束的自由文本来处理关键状态变化。
