# 卧底魔王 Demo UI/UE 优化文档

## 1. 文档目的

本文档用于指导其他 agent 优化当前《假如我是勇者队伍里的卧底魔王》Demo 的视觉表现和交互体验。

当前 Demo 已经具备可玩骨架和暗黑奇幻素材，但整体精致感不足，核心原因不是“装饰不够”，而是：

- 桌面端布局像多份竖屏手机稿横向重复。
- 游玩视图缺少清晰的信息层级。
- 对白、状态、选择、结果反馈彼此分散。
- 状态变化没有成为玩家可感知的“蝴蝶效应”。

本次优化目标是把 Demo 从“可玩的网页原型”提升为“像游戏的视觉小说体验”。

## 2. 开发边界

必须保持：

- 不回到 `persona-library` 改实现。
- 不引入 React、Vite、后端服务或新依赖。
- 不接真实 LLM。
- 不接 Silicon Factory。
- 继续使用：
  - `index.html`
  - `src/app.js`
  - `src/styles.css`
- 修改 `src/app.js` 后运行 `pnpm check`。
- UI / 玩法变更后用 `pnpm dev` 手动验证。

## 3. 当前观察结论

浏览器地址：

- `http://localhost:5177/`

当前优点：

- 美术方向已经比早期壳明显提升。
- 有竖版魔王城背景、角色头像、身份卡、对白框、行动按钮。
- 开始页已经能传达“公开身份 / 真实身份”的双面感。
- 游玩页已经有视觉小说式对白推进。
- 六幕和结局 Demo 骨架已经存在。

当前主要问题：

1. **桌面端画布重复**
   - 当前 `.full-screen-app` 固定 `max-width: 520px`。
   - 页面背景 / 画布在宽屏下呈现出多份竖屏内容并排的观感。
   - 这会立刻破坏精致感。

2. **游玩页顶部空黑过多**
   - 转场后首屏大面积黑色留白。
   - 对白内容和决策区域过低，玩家第一眼看不到主要交互。

3. **对白框和选择区不够统一**
   - 对白框像一张悬浮信息卡。
   - 选择区像按钮列表。
   - 两者没有形成“底部对白 / 命运决策层”的整体结构。

4. **状态反馈太弱**
   - 状态目前偏 debug，核心数值没有成为主体验。
   - 玩家每回合不够明确地看到“我刚刚改变了什么”。

5. **背景抢信息**
   - 魔王城背景氛围好，但符文和高对比暗部较多。
   - 对白框、按钮和状态标签需要更强的可读保护层。

6. **缺少角色站位感**
   - 当前更多是头像卡。
   - 视觉小说常见体验是角色立绘 / side image 与对白框联动，让“谁在施压”更直观。

## 4. 参考原则

本项目不需要照搬现成引擎，但可以借鉴视觉小说的成熟布局规律。

参考资料：

- Ren'Py 文档强调文本是视觉小说和叙事游戏的核心，并区分“角色名 + 对白文本 + 叙述文本”的显示结构。
  - <https://www.renpy.org/doc/html/dialogue.html>
- Ren'Py GUI 文档提供了 namebox、dialogue window、text style 等可定制界面层的思路。
  - <https://www.renpy.org/doc/html/gui.html>
- Arcweave 的视觉小说 CSS 教程展示了角色图像通常贴近底部并与对白框形成一体的页面组织方式。
  - <https://docs.arcweave.com/tutorials/style-editor/css-visual-novel>
- TyranoBuilder 的分支教程说明玩家选择是视觉小说分支体验的关键节点。
  - <https://tyranobuilder.com/tutorials/adding-story-branches-and-player-choices>

提炼成 What-If 的原则：

- 背景负责氛围。
- 角色负责压力。
- 对白框负责叙事焦点。
- 状态 HUD 负责因果反馈。
- 选择卡负责“收益 + 代价”的决策感。

## 5. 目标视觉方向

建议将 Demo 方向定义为：

> 暗黑奇幻视觉小说主舞台 + 中部角色焦点 + 底部命运决策盘 + 行动后状态反馈

关键词：

- 暗黑奇幻。
- 潜伏感。
- 审问压力。
- 魔王城仪式感。
- 精致但不堆装饰。
- 手机优先，但桌面不能像拉伸手机截图。

避免：

- 纯网页卡片堆叠。
- 大面积无意义黑屏。
- 多份竖屏画面横向重复。
- 选择按钮像普通表单。
- 状态只藏在调试面板。
- 紫色 / 金色特效堆满导致主体不清。

## 6. 信息架构建议

### 6.1 开始页

开始页目标：

- 一分钟内讲清楚前提。
- 让玩家愿意点“开始潜伏”。
- 不要像文档介绍页。

建议结构：

1. 背景：魔王城门竖图，居中单画布。
2. 顶部：小型品牌标签。
3. 中上：剧本标题。
4. 中部：双身份切换卡。
5. 中下：三条核心困境。
6. 底部：主按钮。

优化点：

- 桌面端只保留一个居中主画布，外侧为暗色舞台背景。
- 标题和身份卡不应重复出现多次。
- 身份卡可保留，但真实身份 tab 需要更有冲击力。
- 三条困境可以压缩成更像任务目标的短句。

### 6.2 游玩页

游玩页目标：

- 玩家始终知道现在是第几幕。
- 玩家清楚谁在说话 / 谁在施压。
- 玩家清楚自己有哪些选择。
- 玩家清楚上一回合造成了哪些后果。

建议层级：

1. 背景层：当前场景图。
2. 角色层：当前说话者 / 焦点角色立绘或头像。
3. 顶部栏：只保留幕数、场景名和设置入口。
4. 底部对白层：角色名、情绪、对白。
5. 底部决策层：对话结束后展开预设行动和自由行动。
6. 结果层：行动后显示裁决、状态变化、角色反应。

关键调整：

- 对白框固定在屏幕底部，而不是随内容漂浮。
- 决策盘和对白框应共享同一底部区域，像一个可展开控制台。
- 不要在顶部放一整排常驻状态数值。它会抢掉场景和对白焦点。
- 中间舞台不要空着，应放当前说话者或当前施压角色的大头像 / 半身立绘。
- 每个行动后要有明显的状态变化标签。

### 6.3 结算页

结算页目标：

- 像游戏通关卡，不像普通结果卡。
- 明确解释为什么达成这个结局。
- 引导重玩。

建议结构：

1. 顶部：结局类型标签。
2. 主标题：结局名。
3. 中部：结局文案。
4. 状态总结：全部核心状态。
5. 命运因果三条：
   - 最大风险来源。
   - 最大转机。
   - 最大代价。
6. 底部：重新开始。

优化点：

- 结局标题需要更强的字体层级。
- 3 条因果不要做成普通列表，要做成“审判记录 / 命运判词”风格。
- 如果有达成条件，可以用小字显示，但不要喧宾夺主。

## 7. 布局修复方案

### 7.1 桌面端

当前问题：

- 主容器最大宽度太窄。
- 外侧出现类似重复手机画面的观感。

推荐方案 A：手机模拟器模式。

适合快速修：

- `body` 使用暗色背景。
- `.full-screen-app` 固定为单个 9:16 舞台。
- 桌面端居中显示。
- 外侧不要重复背景图。
- 可以加弱阴影和细边框，让它像游戏预览窗口。

建议规格：

```css
.full-screen-app {
  width: min(100vw, 430px);
  height: min(100vh, 932px);
  aspect-ratio: 9 / 16;
  margin: 0 auto;
}
```

注意：

- 如果视口高度不足，应以 `height` 为主，避免底部被裁。
- 不要让页面出现第二份重复画布。

推荐方案 B：响应式桌面游戏舞台。

适合更精美，但改动稍大：

- 桌面端采用 16:9 主舞台。
- 右侧固定状态 / 历史 / 角色栏。
- 底部保留对白框。
- 移动端切回 9:16 单列。

本次建议先用方案 A，成本低，风险小。

### 7.2 移动端

移动端目标：

- 320px 宽度可玩。
- 无横向滚动。
- 底部按钮不被安全区遮挡。
- 对白和选择不互相挤压。

要求：

- 对话框最大高度可控。
- 选择区出现时允许内部滚动或压缩间距。
- 自由行动输入不要挤到一行读不清。

## 8. 对白系统优化

### 8.1 对白框结构

建议对白框改为固定底部结构：

```html
<section class="vn-bottom-panel">
  <div class="speaker-nameplate">伊薇特 · 法师</div>
  <div class="dialogue-window">
    <p>圣光不会留下黑色余烬。至少王立学院的教材不是这么写的。</p>
  </div>
  <div class="continue-cue">点击继续</div>
</section>
```

视觉要求：

- nameplate 要压在对白框上沿，像游戏 UI。
- 对白框宽度接近舞台宽度，但左右保留 12-16px。
- 背景使用深色半透明，不要太玻璃化。
- 字体大小移动端建议 `15-16px`，行高 `1.65-1.8`。
- 对白框高度稳定，避免每句对白跳动。

### 8.2 角色头像 / 立绘

当前头像卡太像资料卡。建议改为：

- 当前说话者头像贴在 nameplate 左侧。
- 如果图片质量足够，使用半身立绘贴近底部对白框上沿。
- 非当前说话者可以在顶部或侧边显示小头像压力条。

角色视觉优先级：

1. 当前说话者。
2. 当前施压角色。
3. 其他焦点角色。

不要每回合展示所有角色，否则会稀释压力。

### 8.3 内心独白

阿斯兰内心独白应与普通对白区别：

- nameplate：`阿斯兰 · 内心`
- 色彩：紫黑 / 冷金。
- 文本可用括号，但不要每句都过长。
- 可以轻微暗化背景，强化潜伏感。

## 9. 选择区优化

### 9.1 决策盘结构

选择区应像“命运决策盘”，不是普通按钮列表。

每个行动卡包含：

- 风险标签。
- 行动标题。
- 一句意图 / 代价预告。

示例：

```text
稳妥
劝队伍先侦查
拖慢推进，但维克托可能继续脑补。
```

### 9.2 选择卡视觉

建议：

- 每张卡高度 `56-68px`。
- 左侧风险标签固定宽度。
- 标题更粗，说明文字更淡。
- hover / active 时边框发光。
- 危险选择用红色边线或角标，不要整张红。
- “离谱”选择可用蓝紫色，但不要全局变紫。

### 9.3 自由行动

当前自由输入是好的，但应更像“密令输入”：

- 输入框文案：`输入你的骚操作 / 暗令 / 解释`
- 提交按钮：`执行`
- 输入区可加小图标，但不要用大段说明。
- 空输入不能提交。

自由行动在视觉上要低于预设选择，但不能像 debug console。

## 10. 状态反馈优化

### 10.1 取消顶部常驻状态条

用户反馈明确指出：**不要上面的一排数值**。

因此不要在顶部标题下方常驻展示 `暴露风险 25`、`勇者信任 72` 这类状态 chip。

顶部区域只保留：

- 当前幕数，例如 `Act 1/6`。
- 当前场景名，例如 `第一幕：城门前的安静`。
- 设置 / 调试入口。

状态数值应该出现在更有意义的位置：

- 行动结算后：展示本回合变化过的状态。
- 高风险阈值触发时：展示短警告。
- 结算页：展示最终状态摘要。
- 调试面板：保留全量状态，供开发检查。

这样玩家不会被数字墙打断叙事，但仍能在关键时刻理解因果。

### 10.2 舞台中部角色呈现

用户反馈指出：**中间太空了，应该放角色头像**。

游玩页中部应放当前说话者或当前施压角色的视觉焦点。

建议优先级：

1. 当前说话者是队友时，显示该角色的大头像 / 半身立绘。
2. 当前说话者是阿斯兰内心独白时，显示阿斯兰头像，并用暗紫色轮廓光。
3. 当前是 GM 叙述或裁决结果时，显示当前场景的 2-3 个焦点角色小头像队列。

建议布局：

- 角色视觉放在画面中下部，位于背景主体和对白框之间。
- 头像 / 半身立绘高度约占舞台高度的 `22%-34%`。
- 不要遮住底部对白框。
- 当前说话者高亮，非当前焦点角色半透明或缩小。
- 如果暂时没有高质量半身图，先用现有 `assets/char_*.png` 做圆形或竖向头像卡。

验收：

- 第一幕初始对白时，中间不再只有城门背景，能看到莱昂 / 伊薇特 / 阿斯兰随对白切换。
- 对白推进时，角色头像或立绘会跟随当前说话者变化。
- 角色视觉不挡住选择按钮和自由行动输入。

### 10.3 回合变化反馈

状态颜色：

- 暴露风险 / 维克托误解：高值危险。
- 勇者信任 / 牧师救赎 / 城防：低值危险。
- 法师证据 / 盗贼把柄：高值危险。
- 蝴蝶偏离：高值荒诞。

行动后必须显示变化：

```text
暴露风险 +8
勇者信任 -3
法师证据 +12
```

建议表现：

- 结果对白前先显示裁决标签。
- 状态变化以小 chip 横向排列。
- 数值变化可以有轻微浮入动画。
- 不要回到顶部常驻状态条。变化反馈应贴近裁决结果或对白框上沿。

### 10.4 阈值警告

达到阈值时显示短警告：

- `暴露风险 >=70`：高压怀疑。
- `法师证据 >=60`：伊薇特正在主动试探。
- `牧师救赎 >=75`：米拉可能为你争取解释机会。
- `盗贼把柄 >=70`：洛克准备公开叫价。
- `维克托误解 >=70`：副官可能灾难性救援。

警告不要弹窗，放在结果区、对白框上沿或角色头像旁即可。

## 11. 结果反馈优化

行动后结果不应该只是下一段对白。建议形成短暂的“裁决回合”：

1. 裁决标签：
   - 成功。
   - 代价成功。
   - 失败。
   - 灾难失败。
2. 一句 GM 结论。
3. 状态变化 chips。
4. 角色反应对白。
5. 进入下一幕按钮。

视觉建议：

- 裁决标签使用强对比。
- GM 结论与角色对白区分。
- “进入下一幕”按钮不要过早抢焦点。

## 12. 背景与遮罩优化

### 12.1 背景

保留现有背景资产，但需要让 UI 更可读。

建议：

- 背景图 `background-size: cover`。
- 不要重复背景。
- 对话 / 选择出现时底部遮罩更强。
- 角色对白时背景亮度降低到 `70%-80%`。
- 选择出现时背景亮度降低到 `60%-70%`。

### 12.2 遮罩

建议使用三层：

1. 全局暗角，保持暗黑奇幻氛围。
2. 底部渐变，保护对白和选择。
3. 顶部轻渐变，保护 HUD。

避免：

- 全屏过黑导致背景素材浪费。
- 高亮符文压过按钮边界。
- 玻璃拟态过多导致所有层级都像卡片。

## 13. 字体与色彩优化

### 13.1 字体

当前字体偏系统 UI。建议在零依赖前提下：

- 保持系统字体作为正文，保证中文清晰。
- 标题使用更有游戏感的字重、阴影和描边，而不是依赖新字体。
- 避免过多 uppercase 英文小标签。

### 13.2 色彩

建议色彩比例：

- 主背景：黑 / 深红 / 暗紫，约 70%。
- 文本和 UI：暖白 / 灰白，约 20%。
- 强调：金色，约 7%。
- 危险 / 魔性：红紫 / 蓝紫，约 3%。

重点：

- 金色只用于主按钮、标题高光、关键边框。
- 紫色只用于魔王 / 蝴蝶偏离 / 魔力。
- 红色只用于危险状态和失败裁决。

## 14. 动效优化

允许 CSS-only 微动效。

建议保留：

- 幕间转场淡入。
- 对白框轻微浮入。
- 选择盘展开。
- 状态变化 chip 浮入。
- 当前说话者头像轻微高亮。

避免：

- 所有按钮都发光。
- 长时间 pulse。
- 大幅位移动画。
- 影响阅读的文字闪烁。

## 15. 代码调整建议

### 15.1 CSS 优先

第一阶段尽量先通过 `src/styles.css` 优化：

- 修复桌面重复 / 裁切问题。
- 重排 `.full-screen-app` 尺寸。
- 重做 `.clean-vn-dialogue-panel`、`.bottom-choice-deck`。
- 新增 HUD 状态样式。
- 优化背景遮罩。

### 15.2 JS 轻改

如果需要，少量修改 `src/app.js`：

- 将 `focusStats` 渲染到顶部 HUD。
- 在 `lastTurn` 结果区渲染 `stateDelta` chips。
- 行动卡显示 `intent`。
- 根据当前说话者控制角色立绘 / 头像高亮。

不要：

- 重写状态机。
- 改结局判定。
- 引入复杂组件抽象。
- 拆成多文件架构，除非非常必要。

## 16. 分阶段实施计划

### 阶段 1：修复画布和响应式

目标：

- 桌面端只显示一个居中的游戏画布。
- 移动端无横向滚动。
- 首屏不出现多份重复内容。

验收：

- `1360px` 宽桌面：只有一个主画布。
- `390px` 移动宽度：内容完整可玩。
- `320px` 移动宽度：按钮和文字不溢出。

### 阶段 2：重做游玩页层级

目标：

- 顶部 HUD 可见。
- 底部对白框稳定。
- 决策盘与对白框形成整体。

验收：

- 玩家一眼能看见第几幕、谁在说话、该做什么。
- 对话推进和选择出现时没有布局跳动。
- 选择区不会遮住对白内容。

### 阶段 3：强化状态反馈

目标：

- 每回合状态变化可见。
- 阈值警告可见。
- Debug 面板不再承担玩家主反馈。

验收：

- 点击预设行动后能看到状态变化 chips。
- 高风险状态有警告。
- 玩家不点齿轮也能理解局势变化。

### 阶段 4：选择卡美化

目标：

- 选择卡表达“行动 + 风险 + 代价”。
- 自由行动像密令输入，而不是普通表单。

验收：

- 每张选择卡有标签、标题、意图。
- 风险标签颜色一致。
- 自由行动输入在移动端可读。

### 阶段 5：结算页 polish

目标：

- 结算页像通关卡。
- 命运因果有仪式感。

验收：

- 结局标题有强视觉层级。
- 三条因果清楚解释结局。
- 重新开始按钮明显。

## 17. QA 检查清单

优化完成后必须检查：

- 打开页面，开始页只出现一个主画布。
- 点击开始后，第一幕转场正常。
- 点击屏幕推进对白，文字不溢出。
- 对话结束后选择盘展开。
- 点击任一预设行动后显示裁决结果。
- 状态变化 chips 可见。
- 可进入下一幕。
- 六幕后能到结算页。
- 结算页能重新开始。
- `320px`、`390px`、桌面宽度都能完整操作。
- `pnpm check` 通过。

## 18. 优先级总结

最高优先级：

1. 修复桌面重复画布。
2. 固定底部对白 / 决策层。
3. 移除顶部常驻状态数值条。
4. 在舞台中部加入当前说话者 / 施压角色头像或半身立绘。

第二优先级：

5. 选择卡显示意图和代价。
6. 状态变化 chips 和阈值警告。
7. 背景遮罩和视觉层级 polish。

第三优先级：

8. 更完整的角色立绘站位。
9. 结算页仪式感。
10. 更细的动效和字体质感。

本轮优化完成后，Demo 应该先像一款真正的暗黑奇幻视觉小说游戏，再继续扩展后端、LLM 或 Silicon Factory 能力。
